# pi-cx release and acceptance

## Asset

`pi-cx-aarch64-apple-darwin.tar.gz` contains `manifest.json`, `bin/cx`, and seven `libtree_sitter_*.dylib` files for language-pack 1.3.1. Its sibling `.sha256` authenticates the archive; the manifest records SHA-256 and byte size for every native file. `vendor/pi-cx/` is generated by postinstall and is never committed.

Build on darwin/arm64:

```bash
cargo build --release --target aarch64-apple-darwin
./scripts/build-pi-cx-asset.sh
PI_CX_ASSET_DIR=/path/to/extracted/asset npm install
npm run verify:pi
```

Before upload, `Cargo.toml`, `package.json`, the `v<version>` tag, `cx --version`, and `manifest.cx_version` must agree. Run `cargo fmt --check`, `cargo test --all`, `cargo clippy --all-targets -- -D warnings`, `npm run typecheck:pi`, and `npm run test:pi`.

## Security boundary

Installing the Git package executes `postinstall`, downloads native release artifacts from the exact package tag, and runs the bundled binary for version verification. Runtime tool calls execute only that manifest-verified binary. The extension writes bundled grammars to cx's shared user cache under a lock; it does not delete indexes or unrelated grammars. Extra-language downloads require explicit UI/RPC confirmation.

## Acceptance record template

Record the immutable Git tag and commit, Pi version, cx/package version, fixture exact counts, staged-install result, offline first-query result for all nine language surfaces, cache repair result, and tampered-binary control. A release is not accepted until the tag URL smoke test succeeds without `PI_CX_ASSET_DIR`.
