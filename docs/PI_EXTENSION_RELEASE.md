# pi-cx release and acceptance

## Assets

Each of the six Rust release targets has a matching `pi-cx-<target>.tar.gz` and `.sha256` asset:

- `aarch64-apple-darwin`, `x86_64-apple-darwin`
- `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu`
- `aarch64-pc-windows-msvc`, `x86_64-pc-windows-msvc`

Every Pi asset contains `manifest.json`, the target-specific `bin/cx[.exe]`, and eight target-specific Tree-sitter grammar libraries from language-pack 1.16.1. The archive checksum and manifest SHA-256/byte-size entries are both mandatory. `vendor/pi-cx/` is generated by postinstall and is never committed.

Build one target:

```bash
cargo build --release --target <target>
node scripts/build-pi-cx-asset.mjs <target> target/<target>/release/cx[.exe] dist
```

The builder obtains the target bundle from the pinned language-pack release, verifies its published digest and size, selects exactly eight grammars, and creates the Pi asset. Native host/target pairs run `cx --version`; cross targets receive static manifest/digest/file-set validation. Postinstall always performs native version and schema probes on the user's machine.

Before upload, `Cargo.toml`, `package.json`, the `v<version>` tag, `cx --version`, and `manifest.cx_version` must agree. Run `cargo fmt --check`, `cargo test --all`, `cargo clippy --all-targets -- -D warnings`, `npm run typecheck:pi`, and `npm run test:pi`.

The release workflow only builds and publishes GitHub release assets. It does not publish crates.io packages or update Homebrew.

## Security boundary

Installing the Git package executes `postinstall`, downloads native release artifacts from the exact package tag, and runs the bundled binary for version/schema verification. Runtime tool calls execute only that manifest-verified binary. The extension writes bundled grammars to cx's shared user cache under a lock; it does not delete indexes or unrelated grammars. Extra-language downloads require explicit UI/RPC confirmation.

## Acceptance record template

Record the immutable Git tag and commit, Pi version, cx/package version, all six asset manifests, native smoke results, fixture exact counts, staged-install result, offline first-query result for all ten language surfaces, cache repair result, and tampered-binary control. A release is not accepted until each tag URL exists and representative native installs succeed without `PI_CX_ASSET_DIR`.
